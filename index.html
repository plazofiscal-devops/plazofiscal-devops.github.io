A Kubernetes platform that keeps tax deadlines on time.

PlazoFiscal helps small accounting firms in Colombia track the tax obligations of their clients. Its platform runs on a three node K3s cluster with rolling releases, scaling that follows the filing calendar, full observability and sign-in with a second factor.

Firms miss deadlines when they are busiest.

Small accounting firms follow the deadlines of dozens of clients in spreadsheets. Load follows the filing calendar, so an outage during a window costs more than at any other time. The product is worth most exactly when its load is highest.

The calendar drives the load

Pick a day of a month, or switch to the income tax season, to see the load the business case expects and the replicas the platform keeps ready for it.

Three service objectives from the business case

Five services keep the obligations of each firm.

An open source microservice example, adapted to tax obligations and moved to Redis. Each obligation has a client, a tax, a due date and a state, and the calendar marks the days with deadlines.

One machine runs the application and every tool.

k3d runs K3s as three Docker containers, one server and two agents, capped at 10 GiB. Three nodes give rolling updates, disruption budgets and the spread of replicas a real effect, and anyone with Docker can run it from a clean clone with make up.

    Every tool has a pinned version and a clear role

    make platform installs each chart with helm upgrade --install and an exact version, next to its values file. A floating version once removed an API that Grafana needs, which is why nothing floats.

    Memory shaped the design more than anything else

    The reference machine has 8 cores and 13.5 GiB, and its desktop takes 3.8. With every tool on, the nodes use 7.2 GiB of their 10. Once, Keycloak, Grafana and Kibana started together, the load average reached 54 and the Kubernetes API stopped answering.

    Releases under load with not one failed request.

    A rolling update replaces pods one at a time without lowering capacity. It is the native strategy of the Deployment, set here to maxSurge 1 and maxUnavailable 0, and the strategy assigned to the group.

        Every service handles SIGTERM and waits 5 s in preStop, so it stops receiving traffic before it closes.

        Default deny, and every open path is proven

        One NetworkPolicy per service opens only the path it needs, and the rest of the traffic stays closed in both directions. K3s enforces policies with its embedded controller, so no extra agent runs on each node.

          How make check-policies proves it

            Redis keeps obligations on a volume that outlives its pod

            todos-api keeps no state of its own. Each user is a hash in Redis, and Redis writes an append only file to a 1 GiB PersistentVolumeClaim of the local-path provisioner of K3s. The readiness of todos-api depends on Redis, so a pod with no Redis leaves the Service without restarting.

            Capacity rises before each deadline and follows real load.

            The HPA of Kubernetes reacts after load rises. The filing calendar is known in advance, so KEDA 2.21 adds it to the HPA. It creates one HPA per served service with a CPU trigger and two calendar triggers in Bogotá time, and the HPA takes the one that asks for more replicas.

            Replicas of frontend, auth-api and todos-api

            It scales down five minutes after a window or the load ends, so it does not oscillate.

            Alternatives

              Five signals reach one dashboard that answers the business.

              Metrics, logs, events, traces and alerts leave the services and meet in Grafana. Jaeger stays on 2.19, since 2.20 removed the v1 API that the Grafana data source calls, and a test against 2.22 answered 404.

                An alert travels from Prometheus to Slack in under two minutes

                A real test, with users-api scaled to zero replicas and then restored, in Bogotá time. The webhook address is a credential, so it lives in a file outside the repository and in a cluster Secret.

                ELK receives every log and every event within a minute

                Fluent Bit collects container logs and Kubernetes events. Logstash names the service, reads the level, keeps the JSON of the service apart and drops health probes before Elasticsearch stores them for 3 days. The JSON of auth-api once overwrote fields of Logstash, so it now lives under app, and Kibana 9.5 needs 1 GiB of Node heap or it dies on restart.

                  One request followed from the browser to the processor

                  Creating an obligation produces one trace in Jaeger across frontend, todos-api and log-message-processor in 577 ms, and the log line of the processor carries the same trace id in Kibana. Signing in gives another trace across frontend, auth-api and users-api in 71 ms.

                  Grafana opens on a dashboard of the business

                  The business row answers what an accountant asks, and below it follow health, alerts, logs, traces and events, so an operator never leaves the dashboard to understand an incident.

                    Kubecost shows the cost of each service from the same Prometheus

                    Kubecost uses reference prices, so it shows how the cost splits between namespaces and services. The free tier covers up to 250 cores and 15 days of metrics.

                    One sign-in with a second factor in front of everything.

                    Keycloak asks for a password and a six digit code before any tool or the application opens. It runs inside the cluster with no outside dependency, and Kibana, whose free tier has no single sign-on, sits behind oauth2-proxy like the rest. One cookie covers every tool for 8 hours.
